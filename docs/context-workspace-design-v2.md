# PCW: инструкции проекта и явный цикл памяти

Действующий руководящий документ исходного проекта. Схема `INSTRUCTIONS.md` заменяет Current; наличие изменений в исходниках не означает их публикацию или установку. [Предыдущий документ](context-workspace-design.md) остаётся историческим описанием.

## 1. Разделение ответственности

PCW предоставляет память проекта, временное хранилище, поиск и операции согласованной записи. Способ ведения конкретного проекта задаёт человек в `INSTRUCTIONS.md` выбранного workspace.

| Место | Назначение |
| --- | --- |
| `INSTRUCTIONS.md` | Главный документ проектных инструкций: цели, ограничения, источники, порядок работы, требования к знаниям и результатам. |
| Основной skill `pcw` | Технический цикл использования памяти; обязательное чтение и соблюдение инструкций проекта. |
| Мини-скилл `pcw-create` | Создание нового контекста по прямому поручению с выбором размещения и задачи. |
| Мини-скилл `pcw-instructions` | Единственное описание процедуры изменения инструкций по прямому поручению человека. |
| `knowledge/` | Постоянные тематические материалы и связи; необходимость одобрения задаётся в INSTRUCTIONS.md. |
| `tmp/<cycle-id>/` | Результаты работы, возвраты исполнителей, состояние задачи и предложения. |

Тело файла инструкций имеет свободный Markdown и не ограничивается прежними пятью полями. Состояние выполняемой задачи не переписывает проектные правила. Инструкции одного workspace общие для использующих его циклов; другие workspace имеют свои файлы.

### Выбор контекста и маршрутизация

Общая процедура выбора описана в [основном skill](../plugins/persistent-context-workspace/skills/pcw/SKILL.md#context-selection) и применяется также дополнительными скиллами. Агент продолжает работу с установленными координатами контекста. Создание нового контекста или переключение на другой требует однозначного указания пользователя. Новый вызов PCW, новая задача, смена рабочего каталога и отсутствие результатов поиска сами по себе такого указания не дают. Если непонятно, к какому контексту обращаться, агент спрашивает до вызова инструментов PCW.

Перед открытием существующего workspace агент проверяет его наличие. `pcw_startup` технически способен создать отсутствующее хранилище, поэтому запрещено использовать его для проверки предполагаемых имён. Этот запрет задаётся инструкциями; отдельная техническая проверка человеческого разрешения на создание не вводится. Разрешённое переключение не закрывает и не очищает прежний цикл.

Основной `pcw` направляет явно запрошенный дополнительный функционал в соответствующий мини-скилл. Пользователь описывает действие обычными словами и не обязан знать отдельное имя: «PCW создай новый контекст под эту задачу» направляется в [pcw-create](../plugins/persistent-context-workspace/skills/pcw-create/SKILL.md), «PCW обнови инструкцию» — в [pcw-instructions](../plugins/persistent-context-workspace/skills/pcw-edit-instructions/SKILL.md). Правило распространяется на все дополнительные скиллы; вопрос о функции не запускает её выполнение.

Мини-скилл создания принимает размещение и задачу в свободной форме. Если размещение не задано, предлагает конкретные варианты по известным путям или принимает место от пользователя; если задача неясна, предлагает варианты назначения либо уточняет описание. Создание начинается после однозначного выбора. Вызов создаёт стандартные инструкции; их адаптация под задачу проходит отдельную процедуру изменения инструкций. Создание пустого контекста не даёт разрешения выполнять будущую задачу или заполнять knowledge выдуманными сведениями.

## 2. Единственный действующий источник правил

Агент читает полный `INSTRUCTIONS.md` до поиска контекста и руководствуется им при работе и подготовке изменений. Файл действует в рамках текущего поручения пользователя и обязательных инструкций среды. Старый чат, прежняя копия файла и стандартный шаблон не заменяют его чтение.

Стандартное содержание имеет один исходный шаблон: [default_instructions.md](../plugins/persistent-context-workspace/pcw_runtime/default_instructions.md). Он используется только для первоначального создания отсутствующего файла. После создания действующие правила находятся в workspace; шаблон не подмешивается при чтении и не восстанавливает удалённые пользователем разделы.

Правила отбора, оформления, структурирования, уплотнения, ведения истории и представления результатов не копируются в основной skill, подсказки MCP или другие действующие инструкции. Эти компоненты направляют агента к `INSTRUCTIONS.md`. Документация описывает механизм, но не задаёт параллельную редакцию проектных правил.

Файл сохраняется при начале, перезапуске, отмене и завершении циклов. Он не включается в векторный индекс. Если ранее инициализированный файл пропал, плагин сообщает ошибку и не заменяет потерянные пользовательские правила стандартными.

### Одобрение знаний

В YAML frontmatter `INSTRUCTIONS.md` предусмотрен параметр:

```yaml
---
knowledge_approval_required: false
---
```

`false` — агент показывает точные изменения в чате и применяет их без вопроса об одобрении. `true` — после показа ждёт явного одобрения этой редакции. Шаблон новых workspace содержит `false`. Существующие файлы не переписываются автоматически: отсутствие параметра сохраняет обязательное одобрение. Недопустимое значение или повтор параметра отклоняется, а не трактуется как разрешение. Свободный текст не заменяет значение параметра.

Изменение самого `INSTRUCTIONS.md`, включая этот параметр, всегда требует явного одобрения по мини-скиллу. Настройка относится только к knowledge; разрешения на внешние действия определяются отдельно. Показ изменений и разбор результата остаются обязательными в обоих режимах. Runtime проверяет политику и ревизии, но не может проверить фактический показ текста в чате.

## 3. Хранилище

```text
<work_root>/.pcw/<workspace>/
  INSTRUCTIONS.md
  knowledge/<id>.md
  tmp/<cycle-id>/
    materials/<id>.md
    proposals/<proposal-id>.json
    proposals/<proposal-id>.md
  .pcw-runtime/
<work_root>/.pcw/.control/<workspace>/
  cycles.json
  instructions-initialized.json
```

`INSTRUCTIONS.md` принадлежит workspace, `tmp` — отдельному циклу. Цель задачи, текущий шаг, ограничения конкретного поручения и препятствия могут записываться обычными временными материалами. Фиксированного Current и инструментов его обновления больше нет.

Служебные записи содержат состояния, идентификаторы и ревизии. Тексты временных результатов и предложений не сохраняются в служебных записях после очистки. Символьные ссылки и выход из выбранного хранилища отклоняются.

## 4. Обычный цикл

1. Агент определяет запрошенную процедуру и контекст по правилам выбора выше. Для обычной работы явное поручение пользователя запускает `pcw_startup` в выбранном существующем workspace с новым `request_id` и `purpose="work"` (по умолчанию). Повтор запроса использует тот же ID; для явного перезапуска указывается `restart_cycle_id`. Упоминание PCW и прежние разрешения не запускают новую работу.
2. Startup возвращает `cycle_id`, полный текст и ревизию `INSTRUCTIONS.md`, а также ограниченный статус памяти без загрузки модели. Агент сначала читает инструкции, затем ищет и читает контекст по поручению. Сведения чата не заменяют этот этап.
3. Агент выполняет задачу и сохраняет временные результаты через `pcw_tmp_write`. Самостоятельная работа и делегирование следуют применимым инструкциям пользователя и среды.
4. После задачи или содержательной части агент формулирует вывод, делает векторный поиск по нему и читает подходящие материалы. По правилам `INSTRUCTIONS.md` готовит изменения существующих знаний, их состава и связей через `pcw_proposal_prepare`. При отсутствии изменений передаёт `changes=[]` и `no_changes_reason`; это результат разбора, а не его замена.
5. Показывает фактические изменения из `review_changes` в чате: темы, полный новый текст либо изменённые фрагменты, удаления, перемещения и связи. Ссылка на файл или общий список тем не заменяют содержание. Объяснения и оформление следуют инструкциям проекта и текущему запросу.
6. Следует `knowledge_approval_required` из инструкций: при `true` ждёт явного одобрения показанной редакции и передаёт реальное `confirmation` в `pcw_proposal_apply`; при `false` применяет показанную редакцию без вопроса и без `confirmation`. Вопросы и исправления продолжают обсуждение; изменённая редакция предъявляется заново. Запись сохраняет временные материалы и запускает индексацию изменённых тел.
7. После завершения задачи, разбора результатов и согласования вызывает `pcw_finish` без отдельного подтверждения закрытия. Он удаляет только `tmp` этого цикла. Незавершённые предложения и индексация блокируют завершение. Отмена пользователем позволяет `cancel:true`, сообщает незавершённые операции и не откатывает постоянные данные.

Подготовка знаний связывается с ревизиями временных результатов и инструкций. Изменение инструкций требует заново сопоставить результаты с действующими правилами; старое предложение, применение которого ещё не начиналось, не применяется. При ошибке записи или индексации временные материалы сохраняются; повторяется та же операция. Начатую по действовавшей политике запись можно довести до завершения после изменения инструкций, затем перед закрытием нужен разбор по актуальным правилам. Одобрение конкретного текста не заменяет разрешения на установку, публикацию или другие внешние действия.

## 5. Изменение инструкций

Процедура описана только в [мини-скилле pcw-instructions](../plugins/persistent-context-workspace/skills/pcw-edit-instructions/SKILL.md). Основной skill направляет туда прямое поручение изменить проектные правила, в том числе названные пользователем Current. Выводы агента и рабочие заметки не являются таким поручением.

При отдельном вызове мини-скилл открывает цикл `purpose="instructions"`. Внутри уже выполняемой задачи использует её цикл и возвращается к работе после редактирования. Самостоятельный цикл инструкций не выполняет обычную задачу, не пишет knowledge и не требует фиктивного разбора результатов работы. Его завершение зависит от завершённости согласования инструкций. Изменение правил внутри рабочего цикла не заменяет разбор результатов этой задачи.

| Инструмент | Техническое действие |
| --- | --- |
| `pcw_instructions_read` | Полный текст файла и его ревизия. |
| `pcw_instructions_prepare` | Сохраняет только временный проект полного текста по прочитанной ревизии и прямому запросу пользователя; возвращает точные изменения для показа. |
| `pcw_instructions_apply` | Проверяет одобренную ревизию и исходный файл, записывает и сверяет текст; эмбеддинги не создаются. |
| `pcw_proposal_read` / `pcw_proposal_discard` | Чтение или отклонение конкретного временного предложения любого вида. |

Предложение инструкций не превращается в предложение знаний и наоборот. Knowledge-операции не могут записывать `INSTRUCTIONS.md`. Конфликт параллельных редакций не перезаписывает чужую работу; нужны новое чтение, подготовка и согласование. Равный текст не требует записи и подтверждения. Пустой текст после явного редактирования остаётся выбором пользователя, а не сигналом восстановить шаблон.

Технические проверки обеспечивают соответствие ревизий, сохранность текста и разделение операций. Они не удостоверяют человеческое происхождение переданного сообщения и не гарантируют смысловое соблюдение инструкций моделью. Явное поручение и подтверждение остаются обязанностями агента; терминал и другие инструменты не служат обходом процедуры.

## 6. Роли и независимость от среды

Основной агент либо назначенный субагент с чистым контекстом выполняет полный рабочий цикл, начиная с `INSTRUCTIONS.md`. Основной агент может быть интерфейсом: передавать поручение, вопросы, предложение и точное подтверждение пользователя, не одобряя за него.

Обычный исполнитель возвращает результаты агенту цикла для временного контекста. PCW не определяет окружение, не выбирает модели и не запускает исполнителей. Стандартный MCP предоставляет одинаковую процедуру разным агентским средам.

## 7. Сохранение и поиск

Знания остаются обычными Markdown-материалами с filename-ID, ревизиями и точными связями. Предъявленные изменения, одобренные при включённом подтверждении, могут создавать, исправлять, перемещать, разделять, объединять и удалять материалы. Изменения входящих ссылок входят в предъявляемый набор.

Токенные окна с перекрытием и эмбеддинги строятся автоматически. Источник эмбеддингов настраивается отдельно. Tmp и инструкции не попадают в постоянный векторный поиск. Неизменённые тела и изменения только ссылок не требуют новых эмбеддингов. Ошибка индекса не стирает сохранённый текст; повтор использует ту же операцию.

## 8. Переход и проверка

При первом запуске обновлённого кода создаётся отсутствующий `INSTRUCTIONS.md` из единственного шаблона либо используется уже существующий файл. Старые root/cycle `current.md`, knowledge и служебные данные не преобразуются в правила и не перезаписываются автоматически. Старые временные файлы подчиняются обычной очистке своего цикла. Циклы прежних версий считаются рабочими; предложения без ревизии инструкций требуют новой подготовки перед обычным применением/завершением.

Проверяются: оба режима одобрения знаний, обязательное подтверждение правки инструкций в обоих режимах, отсутствие обхода через смену режима, первоначальная выдача правил, произвольный Markdown, отсутствие загрузки модели при чтении инструкций, сохранение между циклами, точная редакция для подтверждения, конфликты и частичные записи, изоляция циклов, отсутствие обхода через knowledge, мини-скилл и маршрутизация из основного skill. Проверки кода и упаковки не подменяют проверку поведения агента.
