# Contextopus 1.3.1 — Respect the selected root's vault boundary

This patch is being prepared. Its publication, installation and live migration
results require their own receipts. The published 1.3.0 tag and assets remain
unchanged.

## Fix

Version 1.3.0 could block migration when the selected root had its own
`.obsidian` directory and an ancestor also contained one. Link resolution
reported multiple vaults even though the selected root already defined the
intended vault boundary. An isolated root copy without that ancestor did not
reproduce the actual layout.

Version 1.3.1 gives the selected root's own `.obsidian` boundary priority.
Ambiguity outside that case and existing path/navigation guards remain enforced.
No user directories need to be deleted or moved. Workspace format 4, record IDs,
stored links and unfinished work retain their existing preservation contract.

## Update and retry

Retain the coherent whole-set backup and existing root, extras and service-owner
arrangement described in the [1.3 upgrade guide](1.3.0.md#direct-update-from-11-or-12).
When the 1.3.1 release is verified and installation is authorized, install its
exact wheel rather than replacing or rebuilding the 1.3.0 release assets:

```console
uv tool install --force --python 3.12 ./contextopus_core-1.3.1-py3-none-any.whl
```

Preserve any extras required by the current installation. With the updated
owner, follow `guide(procedure="upgrade")`, obtain a fresh migration preview,
review it and apply its exact revision. Preserve pending proposals and cycle
IDs. Use the retained accepted revision for supported retries; inspect any
reported conflict before preparing a replacement. Do not remove ancestor vaults
or disable path guards to make the preview succeed.

The patch uses the existing release checks and platform CI. Verification must
include the actual nested-vault layout through the installed wheel and MCP.
The green 1.3.0 matrix and historical model/copy evidence do not by themselves
establish execution of this changed path.
