# Contextopus 1.0.0

Contextopus 1.0.0 is validated and installed. Publication uses the verified wheel/sdist and client bundles listed below.

Contextopus replaces the plugin-only delivery with a standalone application: `contextopus-core` distribution, `contextopus` import/CLI, private `pikiby/contextopus-core` repository. The source includes preexisting uncommitted 0.14.0/v4 work; HEAD before transition was 0.13.0. Release comparison must include that baseline.

## Changes

- Shared Application, typed Core/module operation registry and persistent data outside client plugin caches.
- Local HTTP MCP service as the single resource owner for clients, CLI and TUI.
- Workspace module preserves selection, independent reading, explicit/implicit updates, required sources, review, instructions approval and migration behavior.
- Thin native Agent Skills (`w`, `ws`, `wi`, `wc`, `wu`, `wa`, `wr`, `wx`) retrieve one canonical installed procedure.
- Project configuration adapters preserve unrelated settings and reject collisions; revision checks reject stale integration previews.
- Settings consequences and copy-only relocation receipts remain explicit.

## Validation and rollout

- The application is installed through uv with the local embedding extra and CPU-only Torch. Outside-checkout imports and CLI version were verified. The existing pinned Qwen 0.6B profile, dimensions, normalization and cached weights were preserved; real CPU search/read succeeded after migration.
- Authorized migration verified 27 contexts, 235 cards and a 20,932-file receipt. Stable IDs/links, instructions, Current/tmp, pending approval revisions and history were retained. Old originals remain copied/retained with old writes disabled. Persistent default-root binding points at the migrated root. Final post-restart verification found 43 materials in the selected Workspace, with the active cycle/task preserved and no pending proposals or outstanding prepared work; 36 reviewed knowledge records plus PROJECT were updated through the new MCP.
- Fresh Codex app-server verification found one manual Contextopus HTTP MCP server, four tools and all eight bare short skills. It read `core.status` and the canonical upgrade procedure. Both old/new plugin caches remain preserved and disabled. Optional plugin delivery was also checked; it exposes namespaced `contextopus:w` rather than literal `$w`.
- Claude Code native MCP inspection and OpenCode native MCP listing reported connected. OpenCode and Crush independently discovered all eight shared skills. Crush's native workspace API reported a connected four-tool server. These discovery/connection checks used no model turns.
- Model setup tests cover CPU/CUDA/MPS selection, stale plans and atomic failure recovery. Application/HTTP tests use real LanceDB and deterministic fake embedding providers; these do not establish real GPU inference.
- Wheel/sdist plus four client bundles build successfully. Artifact verification checks checksums, required runtime/resources, canonical skill bytes and version consistency. A clean temporary wheel installation was verified outside the checkout.
- Actual headless TUI captures use synthetic EXAMPLE data; see [capture provenance](../media/tui/README.md). The installed TUI separately passed a real 79×24 terminal smoke: selection stayed visible, Settings opened, Q returned, Q exited successfully, and the owner/settings revision stayed unchanged.

## Validation matrix and limits

The [six-job Linux/macOS/Windows × Python 3.12/3.13 matrix](https://github.com/pikiby/contextopus-core/actions/runs/38671106182) passed full tests, builds, asset verification and wheel installation. Linux/macOS jobs each reported 372 passed, 6 skipped and 64 subtests passed. Windows jobs each reported 351 passed, 27 skipped and 53 subtests passed.

Five recognized legacy contexts remain uninitialized until their complete instructions receive explicit human review. Session search is an adapter for an independently running compatible session service; its installed availability does not include that external service. Real GPU inference and model-driven full workflows in every coding host are outside the performed checks. GraphFrontier and the skills registry remain future work. PyPI publication is not part of this release.

Cross-platform scope: Windows platform-specific skips cover the legacy 0.14 POSIX shell-launcher fixtures in `test_startup.py` (16 launcher tests; the pure version-bound check remains portable) and three `/bin/sh` integration tests in `test_contracts.py`. Portable manifest/resource checks and the new Core, Workspace, real LanceDB, HTTP MCP, model-setup and native configuration tests remain enabled. Additional skips cover POSIX access-mode semantics and optional external Codex/Qwen fixtures that require explicit provisioning. Portable standalone runtime failures remain part of the matrix.
