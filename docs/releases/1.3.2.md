# Contextopus 1.3.2 — Initial rules, native routing and legacy identities

This patch is being prepared. Publication, installation and acceptance of the
final artifacts are separate checks. The published 1.3.0 and 1.3.1 tags and
assets remain unchanged.

## Initial rules and native MCP routing

The Workspace procedure now separates the first complete INSTRUCTIONS reading
from conditional project reading. A new independent retrieval task must obtain
the complete current rules before searching. `reread_instructions=false` permits
reuse only when this agent already has those rules for the current task and
context. Project reading remains conditional on needing the project's purpose,
goals or boundaries. The first search inherits the selected context's algorithm
and limits unless the user supplied others; later adjustments need an observed
reason in the result.

MCP initialization instructions explicitly direct agents to the Contextopus
tools advertised by their client, allowing native server prefixes. A supplied
`work_root` identifies context data. Shell commands, direct context-file reads,
generic code search and web search must not replace Contextopus operations.
Native skill loading and the readers required by declared external sources
remain available. Connection failures should be reported instead of bypassed.
Tool names, query/write boundaries and existing approval rules are unchanged.

These changes clarify the delivered instructions. Protocol and contract tests
do not establish native model compliance. Acceptance must distinguish actual
skill activation, delivery of instructions to the model, initial rule reading,
inherited search settings and useful evidence-based reading. Earlier technical
MCP-only success does not close ordinary skill-procedure acceptance.

## Scoped legacy filename identities

The candidate migration handles colliding filename identities in format 0/1
contexts through a reviewed context/path mapping. Canonical IDs in format 2 and
later retain their existing identity contract. The mapping and its dependencies
are bound to the migration revision and retained receipt. Pending proposals
keep their original reviewed bytes and approval digest; technical execution
overlays adapt migrated identities without replacing that approval.

Ambiguous references must report a conflict rather than silently choose a
target. Foreign contexts are not implicitly migrated. Review found a case where
an exact foreign wikilink resolved correctly, then a second local-alias lookup
redirected its canonical ID to a colliding legacy filename. The correction
preserves the decoded canonical target, checks pending `link_ids` against the
reviewed graph and respects explicit foreign ownership in `link_targets`.
Inconsistent reviewed graphs block before application. Workspace format remains
4.

## Candidate verification and limits

The migration run passed **17 new cases and five historical cases** in 75.30 s.
Its scope includes scoped identities, canonical foreign targets, immutable
proposal approvals, interruption/retry, retained maps and root relocation. The
same independent foreign-link reproducer that exposed the defect then passed:
the original foreign path and canonical ID were retained after migration.

One complete Linux source-suite run finished with **792 passed, two failed,
10 skipped and 62 passed subtests** in 930.44 s. Both failures were version
contracts: the hidden native-plugin manifest and the test interpreter's
installed distribution metadata still reported 1.3.1 while the project declared
1.3.2. These are packaging/environment checks to close, not assertions to weaken.
The inspected source/test fingerprints stayed unchanged during that run.
These results do not constitute a fully passing final-artifact or platform gate.

After aligning both native manifests and rebuilding only the repository's
editable project metadata as 1.3.2, the complete contract and release-readiness
files passed: **40 passed and two passed subtests** in 19.35 s. Other dependencies
and the host installation were unchanged. This focused result closes the two
version failures; the earlier full-suite result remains as reported above and
was not rerun or relabeled as an all-passing run.

The installed 1.3.1 native-client checks retain their separate scope. Codex passed
the bounded scenario; Claude completed retrieval with repeated guide calls.
OpenCode retrieved evidence but skipped the initial full rules and supplied
`N=15` rather than inheriting the selected settings. Crush received its native
skill with MCP connected, but bypassed the advertised tools. Its separate
MCP-only capability success does not close that behavior failure. Native model
acceptance of the 1.3.2 candidate remains pending; instruction and protocol
changes alone do not establish a behavioral correction.
