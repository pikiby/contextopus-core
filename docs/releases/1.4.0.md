# Contextopus 1.4.0 — Optional working memory

Prepared source update. Publication and installation are separate verification
steps; the presence of this document does not establish either.

## Behavior

- `.tmp` holds optional shared assignments, inputs and intermediate findings.
  Short answers and direct knowledge corrections need no temporary report.
- Working cards reuse Markdown, YAML IDs, descriptions, native links and required
  sources. Readable names describe their content. Agents pass references using
  their native communication tools instead of repeating common briefs.
- Startup records the exact user request; `workspace.clarification_add` preserves
  relevant follow-ups verbatim. `workspace.cycles_list` discovers unfinished work.
  The procedure requires inspecting old work before opening another cycle.
- `workspace.tmp_delete` removes an unneeded card. The dedicated MCP `finish`
  tool closes one bounded work cycle. Both respect dependencies and the separate
  `cleanup_approval_required` setting. New contexts default to false; users can
  enable confirmation. Explicit existing choices remain unchanged. Disabling it
  removes the extra confirmation question, not revision or pending-work checks.
- Temporary cards may link to temporary or permanent records. Permanent records
  cannot depend on temporary data. Pending proposals and indexing must finish
  before ordinary closure; pause and handoff preserve the needed files.
- New migration snapshots use hidden `.backups` directories so recovery copies
  stay out of normal vault navigation. Existing recorded backup paths remain
  supported; neither old nor new snapshot trees are recursively copied.
- No per-file disposition ledger, mandatory no-change proposal or folder-checksum
  proof of semantic review is required. Agents still assess evidence before
  updating permanent knowledge and show actual changes under the existing policy.
- Every permanent record has a derived `context/<owner>` YAML tag. Other tags are
  preserved. Ownership remains the search category, so tags do not introduce a
  competing classification. Context names are unique under Unicode NFKC and case
  folding within one storage root.

MCP now advertises `guide`, `read`, `write` and `finish`. Existing operation names
remain available through the common registry used by MCP and CLI. Native-client
permissions continue to apply; Workspace settings do not override host policy.

## Upgrade

Hermes is available as a fifth native client through
`contextopus integrate hermes --user [--hermes-home <directory>]`. The adapter
previews YAML configuration and the seven canonical native skills, then applies
the reviewed changes with `--apply`. It reuses the existing HTTP MCP owner and
Workspace root. The `contextopus-hermes-1.4.0.zip` release bundle includes the
skills and [Hermes setup guide](../integrations/hermes.md); `SHA256SUMS` covers it
with the other client bundles. Installation and live-client evidence remain
separate from package verification.

Workspace format 5 moves `tmp` to `.tmp`, assigns readable temporary filenames
while retaining IDs, updates technical references and adds context tags. Migration
retains recoverable source/control snapshots. Original proposal and review bytes,
approval revisions, custom rules, existing policy values and unfinished work are
preserved. Execution overlays adapt technical paths without approving old work.

1. Preserve a coherent backup of the existing data root, installed package and
   native-client configuration. Keep the current root and inference extras.
2. Test the candidate and migration on an isolated copy, including pending work
   and interrupted retry. Do not run old code against migrated storage.
3. Replace the package, restart the single shared owner, inspect the selected
   context's upgrade plan and apply the exact reviewed revision. Earlier formats
   pass through the required transitions; no intermediate package is required.
4. Resolve reported name collisions or permanent references to temporary data
   through their normal procedures. Migration never silently merges contexts or
   deletes useful content to satisfy the new format.
5. Refresh managed skills and used procedures, preview the bundled documentation
   update, then verify native discovery of all four tools and a real context read.

Existing contexts retain a true fallback when the cleanup policy is absent. This does not change existing
knowledge or instructions approval choices. A user can change it through the
usual settings review; creating a context offers it in the standard settings set.

## Verification

The implementation report records the actual test runs, package smoke checks and
their limits. Deterministic tests establish tool behavior; they do not establish
that every model obeys the procedure. Temporary evidence remains outside ordinary
knowledge search and permanent Git history.
