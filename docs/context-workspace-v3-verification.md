# PCW: проверка версий

> Примечание: личные пути и идентификаторы трасс/материалов обезличены; результаты измерений сохранены.

## Проверка кандидата 0.13.0 — 7 октября 2026

- Добавлена явная настройка create_required_sources для создания нового контекста. Проверены оба значения, отказ при пропущенном выборе и некорректных типах, сохранность инструкций прежних контекстов и повтор принятого старой версией запроса создания, включая незавершённый.
- Блок required_sources сохраняется в теле материала и возвращается без потерь при повторных read/read_many. Эти тесты проверяют хранение, а не исполнение агентом внешнего запроса. Свежая проверка каждого источника при каждом получении материала закреплена в процедурах и описаниях MCP.
- Добавлен pcw-analyze, pcw-instructions переименован в pcw-edit-instructions; отображаемые названия приведены к именам вызова. Проверены ссылки и комплект из восьми скиллов; все восемь прошли quick_validate.py. Проверка журнала подтверждает доступность результатов чтения, объявленного перехода по связи и ошибки, не выдавая чтение за доказанное использование знаний.
- Профильный прогон: **62 passed**. Полный прогон: **251 passed, 5 skipped, 64 subtests passed**, семь предупреждений об устаревающих API LanceDB. Пропущены opt-in проверки реального агента. Реальный stdio MCP и регистрация двух инструментов проверены контрактным набором. Зависшие на LanceDB прогоны в песочнице остановлены; успешные проверки выполнены вне неё с временными хранилищами и детерминированными эмбеддингами.
- Проверен исходный кандидат 0.13.0. Публикация, установка и изменение пользовательских контекстов в этот тестовый прогон не входили. Универсальное соблюдение новых процедур моделью и экономия токенов не проверялись.

## Два MCP-инструмента в 0.12.0 — 5 октября 2026

- Итоговый полный прогон: **237 passed, 5 skipped, 64 subtests passed**. Пять пропусков — opt-in проверки Codex; семь предупреждений относятся к прежним API LanceDB. Проверены whitelist операций, разделение чтения и изменений, типы и лишние параметры, отсутствие открытия хранилища при некорректном запросе, согласование и конфликты редакций через новый вход, сохранение имён операций и ошибок в SQLite.
- Реальный stdio MCP публикует ровно `pcw_query` и `pcw_execute`. Через них проверены создание, поиск, чтение, временные результаты, предложения, применение, инструкции, восстановление производного хранилища и завершение. Все 42 схемы доступны через describe; получение справки не создаёт файлов. В раннем общем прогоне был единичный тайм-аут stdio; отдельный повтор прошёл. Тестовый stderr переведён из непрочитанного pipe в файл, чтобы логирование не могло заблокировать сервер. Итоговый общий прогон прошёл полностью.
- В отдельном Codex проверены наличие двух инструментов и работа памяти через host API, а также обнаружение семи скиллов. Реальный модельный сценарий создания прошёл за **106,67 с**: модель вызвала `pcw_query/describe`, затем `pcw_execute/workspace_create`; тест не создавал контекст за модель. Проверены выбранные координаты, INSTRUCTIONS, PROJECT, пустые knowledge и отсутствие startup. Это подтверждение конкретного сценария, а не гарантия поведения всех моделей. Сценарий двухходового одобрения и отдельный Qwen-сценарий заново не запускались.
- Первый модельный прогон истёк по тайм-ауту. В следующем прогоне журнал показал дефект тестовой копии: переносились только skills, без относительного ресурса `pcw_runtime/default_instructions.md`. Модель нашла шаблон в исходниках и успешно завершила создание. Тестовое окружение исправлено: теперь копируется пакет с его относительными ресурсами. Публичные события этого прогона сохранены в `/tmp/pcw-0120-host-traces/` для локальной диагностики; это временный артефакт, не knowledge.
- Все семь скиллов прошли `quick_validate.py`. Установлен локальный пакет **0.12.0** через менеджер плагинов Codex; все **43 файла** совпали с исходниками, проверка зависимостей вернула ready. В текущей рабочей сессии доступны оба новых инструмента; вызов `pcw_query(operation="describe", arguments={"operation":"workspace_create"})` успешно вернул схему создания. Формат workspace остаётся **1**. Пользовательские контексты в этой проверке не создавались и не обновлялись.
