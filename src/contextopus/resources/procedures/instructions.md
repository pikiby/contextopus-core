# Edit Contextopus instructions

Use the two [MCP entrypoints](procedure:workspace#mcp-calls): `contextopus_query` for reads and `contextopus_execute` for changes. The names below are operations; place their parameters in `arguments`. Describe only an unknown signature.

This skill defines the instructions-edit procedure. Project rules themselves live only in the selected workspace's `INSTRUCTIONS.md`. Do not initiate an edit from task results, working notes or an inferred preference.

1. Establish the exact user request and resolve the existing workspace under the main skill's [Context selection](procedure:workspace#context-selection) rules. An instructions-edit request alone does not authorize creating a context or choosing a different one. If a cycle for that workspace is active, use its `cycle_id`; otherwise call `startup` with a fresh `request_id` and `purpose: "instructions"`. Retry with the same request ID. This standalone cycle is only for editing instructions, not ordinary task execution or a knowledge update.
2. Read the full `INSTRUCTIONS.md` and revision returned by startup, or call `instructions_read` in an existing cycle. Follow its current rules while reviewing the request, within the current user's authority and applicable host instructions. A direct request to revise a rule is authority to propose that revision, not permission to silently change unrelated rules. For an actual startup failure, use [Setup](procedure:reference/setup).
3. Compose the complete revised Markdown within the requested scope. Preserve unrelated instructions and frontmatter. Pass the complete text, read revision and actual request to `instructions_prepare` as `content`, `expected_revision` and `user_request`. This writes only a draft in tmp; no headings are required. Settings are independent: `allow_implicit_updates` permits starting work without explicit Contextopus invocation; `knowledge_approval_required` controls approval of shown knowledge/PROJECT changes; `git_history_enabled` enables local permanent history; `material_max_tokens` is an optional positive limit or null. Changing any setting is an instructions edit. Missing legacy values remain restrictive, never inferred from prose. To revise an unapplied draft, reuse its `proposal_id`.
   `create_required_sources` controls authoring required source links under the workspace's rules. Enabling it includes the standard template's Required sources rule unless the user specifies different criteria. Disabling authoring does not cancel checks of existing marked sources; use the [required-source procedure](procedure:reference/required-sources).
4. Show the actual `review_changes` in chat: the affected rules, before/after text and any removals. Follow the workspace's presentation rules and the user's current request. A file link or summary does not replace the changed text. Questions and corrections continue the discussion without changing the file; prepare and present each revised version again. `proposal_read` can retrieve a draft when needed.
5. Regardless of the knowledge approval setting, only after explicit user approval of the shown revision, call `instructions_apply` with its `proposal_id`, `expected_revision` and the actual `confirmation`. Old approvals, silence, self-approval and automatic permission review do not authorize it. The tool checks revisions and verifies the written text; it cannot authenticate the origin of a message. A conflict requires reading the changed file, preparing a new revision and presenting it for new approval. Retry a partial write with the same proposal. Do not bypass this procedure through direct writes, knowledge tools or workers. After success, follow the newly applied instructions.
6. If preparation reports `no_changes`, explain that the requested text already matches; no approval or apply is needed. Discard rejected drafts with `proposal_discard`. For a standalone instructions cycle, finish after the discussion and proposals are resolved through `finish`, without separate closure permission or a knowledge proposal. It clears drafts but preserves `INSTRUCTIONS.md`. Actual user cancellation permits `cancel:true`. When called within a work cycle, return to that task instead of closing it; editing instructions does not replace its result review.
