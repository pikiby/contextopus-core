# Analyze Contextopus use

Use the two [MCP entrypoints](procedure:workspace#mcp-calls). Read-only analysis uses `contextopus_query`; it needs no startup, Current, tmp, proposal or finish. Follow the main skill's context-selection rules and read INSTRUCTIONS.md and PROJECT.md. Do not edit knowledge or repair the behavior being analyzed.

1. Establish the selected workspace and scope: task, cycle, period or user-selected transcript, including another agent's session. Ask if the target is ambiguous; do not guess a session from a directory or timestamps. Freeze an upper time bound before querying so this analysis's own calls do not inflate the inspected period.
2. Read [history and analytics](procedure:reference/history-analytics). Query `analytics_query` with `target_workspace` and the selected `task_id`, `cycle_id`, `since`/`until` or `import_id`. Page with offset/limit through the requested scope; a first page is not the whole history. For cycle/task filters, note that independent reads may have neither ID and cannot silently be attributed to that agent. If historical rules matter, retrieve the relevant instruction revision rather than judging old work under today's settings.
3. Read selected events with `analytics_read(event_id)`; retrieve referenced bodies with `analytics_blob_read(blob_id)` where needed. For each finding retain exact event IDs, operation, parameters, returned material IDs/revisions and outcome. Distinguish a search match from a returned full body; count read_many bodies, repeated reads and unique materials separately. A successful read with `from_id` records declared link traversal; an unlabelled read is not proof that a link was ignored. Inspect prepared/applied changes and errors, not just call counts.
4. Assess actual use: connect a claim or action to the material read only when the returned content and task/answer evidence support that connection. Reading alone does not prove application. Without a selected transcript, external source reads, required-source refreshes, the final answer and entirely skipped Contextopus calls may be unobservable. Say "not established" rather than "not done". A `started` record has unknown outcome. Do not infer authorship from timestamps or observed file changes.
5. Import a transcript only when the user selected that exact file and authorized its analysis/import: `contextopus_execute(operation="analytics_import", arguments={"source_path": ..., "adapter": ..., "user_request": ...})`, with `session_id` when required. Use `codex-jsonl` or portable `workspace-session-v1`; do not discover or read other sessions automatically. Imported events remain unmatched without independent evidence. Content with marked required sources follows the [same fresh-check procedure](procedure:reference/required-sources); fresh checks during this analysis do not prove that the earlier agent performed them.
6. Report in the conversation language: scope and coverage; a table **finding | evidence event IDs | established fact or inference**; measured read/search/link/change/error counts; unknowns and concrete corrections supported by the evidence. Sum of Contextopus durations is not total task time. Bytes are not tokens; token savings, cost and causal improvement remain unmeasured without complete host usage and comparable runs. Keep this separate from benchmark execution.

Return the analysis in chat. Only on an explicit request to retain an assessment, use `analytics_evaluate(criterion, assessment, event_ids)` through contextopus_execute; this writes analytical evaluations, not knowledge. A request to analyze does not itself authorize importing arbitrary histories, rewriting instructions or implementing fixes.
