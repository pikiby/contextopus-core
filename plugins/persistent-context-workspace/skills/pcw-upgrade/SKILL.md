# Upgrade context format

Use the two [MCP entrypoints](../pcw/SKILL.md#mcp-calls): `pcw_query` for reads and `pcw_execute` for changes. The names below are operations; place their parameters in `arguments`. Describe only an unknown signature.

1. Resolve the user's exact context, list of contexts or bounded directories. Follow [context selection](../pcw/SKILL.md#context-selection). Enumerate only those directories, never the whole computer.
2. Call `upgrade_plan` for each selected existing context. It returns compatibility, the source revision, technical changes, saved unfinished work, blockers and `project_description`. Inspect these even when the format is already current; compatibility does not mean that work is finished or project content is complete. Explain each unfinished work item using its request/task and material titles; distinguish prepared proposals from applied changes awaiting closure. An open record does not prove that an agent is running. An unknown structure requires inspection/restoration; do not guess its version. An already compatible format requires no rewrite merely because the plugin was updated.
3. Show affected paths and explain that the snapshot retains the entire workspace, including tmp, plus its control state. Format 2 places stable IDs in YAML, gives knowledge files descriptive names, converts legacy source blocks, and indexes them in the common category-aware RAG. Compatible unfinished work keeps its IDs, immutable proposals and approval states; the migration retains technical path/format mappings for later application. Do not apply, discard or cancel that work. If `ready` is false, describe the exact blocker and affected work. Otherwise call `upgrade_apply(expected_revision, user_request)` for a direct request, or `upgrade_apply(expected_revision, automatic=true)` for detected incompatibility. Do not invent a user request or approval. Use `resume_revision` for a pending migration.
4. Report verified format, backup paths, preservation of unfinished work, project-description status and any pending index repair. `missing`, `empty` or `placeholder` means PROJECT still needs content; state that explicitly. `present` does not establish accuracy or completeness. Retry interrupted migration using its original revision and retained snapshot. Source conflicts require inspection. Format completion requires both file conversion and successful shared indexing; `index_pending` is not completion. Resume the original PCW operation after success, under its original active context's instructions.
5. Preserve custom INSTRUCTIONS verbatim. A new default template does not authorize replacement. Reclassifying old goals, splitting mixed knowledge and revising instructions are separate requested rework/instructions procedures. Do not turn format migration into substantive editing.

If the user also requested filling PROJECT, follow the [work cycle](../pcw/SKILL.md#work-cycle): read workspace instructions and relevant existing knowledge, verify missing facts from permitted project sources, then prepare the supported description with `project_update`. Show its actual text and apply through `project_apply` under the workspace approval policy. Do not invent goals or apply another task's pending proposal. Otherwise report the unfilled description as remaining content work.
