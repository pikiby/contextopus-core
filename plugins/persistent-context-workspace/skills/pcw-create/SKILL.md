# Create context

Use the two [MCP entrypoints](../pcw/SKILL.md#mcp-calls): `pcw_query` for reads and `pcw_execute` for changes. The names below are operations; place their parameters in `arguments`. Describe only an unknown signature.

1. Follow [context selection](../pcw/SKILL.md#context-selection). Establish the actual creation request and project/task scope. Accept any clear natural-language description; do not require parameter names.
2. Resolve placement. If unspecified, offer concrete full paths under the relevant project or another known location, plus a user-chosen location. Do not invent a shared directory. Show `<work_root>/.pcw/<workspace>`; inspect it without startup. An existing context is not overwritten or silently renamed. Ask how to proceed if the chosen name exists. Include any needed parent directory creation in the proposed placement.
3. Ask **separate questions** for each unanswered setting: may work update this context without an explicit PCW invocation (`allow_implicit_updates`); must shown knowledge/PROJECT changes wait for approval (`knowledge_approval_required`); enable local Git history (`git_history_enabled`); maximum knowledge-material size (`material_max_tokens`). For the size question, offer these choices in this order, in the conversation language: **1024 tokens (recommended)**, **Another limit**, **No limit**. The first choice is the standard from the packaged template; ask for a positive token count only if the user chooses another limit without specifying it. No limit means null. Explain choices in ordinary language. Do not ask again for supplied values. Wait for an answer; silence or a preselected option is not a selection.
   Ask one further separate question: "Should the agent add required source links for information that must be checked anew whenever its material is read?" Offer yes/no in the conversation language. Store the actual answer as `create_required_sources`; do not derive it from general permission to write. This is the fifth creation setting. Existing required-source blocks are always checked, regardless of this authoring choice.
4. Read the packaged [default instructions](../../pcw_runtime/default_instructions.md). Compose initial INSTRUCTIONS using that one template and the five selected settings; compose PROJECT from the user's stated purpose, goals and boundaries. If source links are accepted, include the template's Required sources rule directing the agent to create them under its stated criteria. If declined, keep the setting false; no authoring obligation is enabled. Show the resulting instructions, project text, settings and absolute destination so the agreed creation is concrete. Do not import unapproved facts from chat as knowledge.
5. Call `workspace_create(request_id, instructions_content, project_content, user_request)` with those exact texts and the user's creation request. Retry identical input with the same request ID. Creation initializes no task and opens no cycle. Verify returned path, settings and independent Git status.
6. If the user also authorized actual work, begin the [work cycle](../pcw/SKILL.md#work-cycle). Otherwise report creation and stop; an empty new context needs no fabricated knowledge, proposal or finish call. Keep the established coordinates for continuation.
